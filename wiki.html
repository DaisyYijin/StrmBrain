STRMhub Wiki

115 网盘 STRM 生成与影视整理工具：转存下载、自动分类整理、STRM 同步归档， 基于 Emby 302 重定向实现云盘原画直连播放 —— 不占本地硬盘，直接用网盘带宽看原盘。

Python 3.12 + FastAPI Vue 3 单页前端 Docker amd64 / arm64 Emby 302 直连播放

# 项目简介

STRMhub 是一个面向 115 网盘的影视资源管理工具，解决「网盘资源如何接入 Emby 媒体库并以原画质直连播放」的完整链路问题。核心思路：

⬇️

转存下载

115 分享链接转存 + 磁力 / HTTP / FTP / 电驴离线下载，合并为单一输入框，自动识别链接类型。

🗂️

影视整理

TMDB 匹配 + AI 辅助识别，按电影 / 电视剧 / AV 自动分类、重命名、洗版去重。

📄

STRM 同步

为视频生成 .strm 索引文件，图片 / NFO / 字幕直下本地；增量同步仅处理差异文件。

▶️

Emby 播放

STRM 指向本服务 302 跳转接口，播放时实时获取 115 直链，云盘原画不占本地空间。

ℹ️默认访问 http://服务器IP:8000，默认账号 admin / admin123，首次登录后请立即修改。

# 核心功能

转存下载

  • 合并离线下载与分享转存为单一输入框，自动识别链接类型：115 分享链接获取文件列表后转存，磁力 / HTTP / FTP / 电驴链接直接添加为离线下载任务。
  • 转存 / 下载完成后自动触发影视整理。

影视整理

  • 扫描 115 网盘源目录，通过 TMDB 匹配影视信息，按电影 / 电视剧 / AV 自动分类移动。
  • 支持二级分类自定义根目录（MoviePilot 式 YAML 分类规则）、重命名规则（完整 / 常规 / 精简三档预设）。
  • 洗版策略：SHA1 去重 + 分辨率 / 编码 / HDR 等多维比较（YAML 可配置）。
  • AI 辅助识别：TMDB 匹配失败时调用 OpenAI 兼容 API 从文件名提取标题重新搜索。
  • 整理完成后非视频文件自动归入冗余目录，源目录自动清理空文件夹。

同步归档

  • 全量同步：扫描网盘目录，视频生成 .strm 文件（内容指向本服务 302 跳转接口），图片 / NFO / 字幕等元数据直接下载到本地。
  • 增量同步：通过清单文件（file_id + SHA1）对比网盘与本地差异，仅处理新增 / 变更 / 移动 / 删除的文件，支持 Cron 定时执行。
  • 上传同步：将 Emby 刮削产生的 NFO / 图片 / 字幕上传回 115 网盘。

Emby 集成

  • STRM 文件通过本服务 302 重定向实时获取 115 直链，播放时直接使用网盘带宽，无需下载到本地。
  • 同步完成后自动触发 Emby 媒体库刷新；支持入库 Webhook 通知。

特色工具

  • 媒体库封面生成：为 Emby 所有媒体库自动生成拼图封面（anime / starfield / featured / random 四种样式）。
  • 115 文件夹清空：定时清理网盘指定文件夹；支持清空回收站。
  • STRM 批量替换：批量替换 STRM 文件内的 URL 字符串（迁移服务器时非常有用）。
  • 缺集检测：对比 TMDB 查找剧集缺失情况。
  • 目录监控：watchdog 递归监控本地目录变化。

# 快速部署

方式一：Docker Compose（推荐）

新建 docker-compose.yml：

# docker-compose.yml
services:
  strmhub:
    # 方式一：使用 GitHub Actions 自动构建的镜像（推荐，无需本地构建）
    image: ghcr.io/daisyyijin/strmhub:latest
    # 方式二：本地构建（注释掉 image，取消注释 build）
    # build: .
    container_name: strmhub
    restart: unless-stopped
    ports:
      - "8000:8000"
    volumes:
      - strmhub_data:/app/data       # 账号、Cookie、同步清单、备份
      - strmhub_config:/app/config     # 设置、管理员账号、同步计划
      - strmhub_log:/app/log         # 运行日志
      - strmhub_media:/media         # STRM 文件输出目录（Emby 读取）
    environment:
      - TZ=Asia/Shanghai

volumes:
  strmhub_data:
  strmhub_config:
  strmhub_log:
  strmhub_media:
$ docker compose up -d

启动后访问 http://服务器IP:8000。镜像由 GitHub Actions 自动构建，支持 amd64 / arm64 双架构。

方式二：Windows 本地运行

项目自带 start.bat 一键启动脚本：自动定位 Python 3.12 环境，缺少依赖时用清华镜像源安装 requirements.txt，随后启动 uvicorn 并自动打开浏览器。

也可以手动运行：

cd backend
pip install -r requirements.txt
python main.py

健康检查

镜像内置 HEALTHCHECK，探测公开接口 GET /api/health；手动验证服务可用： GET http://服务器IP:8000/api/health。

# 使用流程

核心配置 — 扫码登录 115 账号；配置 Emby 地址 / API Key、TMDB API Key（可选镜像域名）、STRM 服务器地址。
转存下载 — 粘贴 115 分享链接或磁力 / HTTP / FTP / 电驴链接，自动转存到网盘并触发整理。
整理功能 — 配置整理目录、分类规则（二级分类 YAML）、重命名规则（完整 / 常规 / 精简）、洗版策略。
同步归档 — 执行全量同步生成 STRM 文件到 /media，设置增量同步 Cron 定时计划，配置上传同步。
通知配置 — 按需配置企业微信 / Telegram / QQ / Bark / Server酱 / Webhook 通知渠道与事件规则。
💡STRM 目录接入 Emby 后，播放时本服务通过 302 跳转把请求转给 115 直链 —— 媒体服务器只看到「一个 URL」，播放带宽全部走网盘，本地零存储成本。

# 通知与集成

通知渠道

  • 新渠道（notification_manager）：Telegram、Bark、Server酱、Meow、Webhook、企业微信，支持事件规则（哪些事件发到哪个渠道）+ 模板渲染。
  • 旧渠道（settings 页）：企业微信、Telegram、QQ，带「发送测试」按钮。

企业微信自建应用

支持 URL 验证与消息推送（AES-256-CBC 加密），配置回调地址后可在企业微信里直接发文本指令控制： handle_command 模块解析指令并执行（如触发整理 / 同步）。

Emby Webhook

兼容多格式 payload（Emby 新旧版本），Token 可选校验，仅处理入库事件并触发通知，可配合入库刷新链路使用。

WebSocket 进度

WS /ws/progress 实时推送任务进度（整理 / 同步 / 下载等），前端进度条与日志面板均基于此实现。

# 常见问题

播放时是走网盘带宽还是本地带宽？

走网盘带宽。STRM 文件内容是本服务的一个 URL，Emby 请求该 URL 时服务端 302 跳转到 115 直链（直链有 10 分钟缓存），客户端直接从 115 拉流 —— 本地只保存 KB 级的 STRM 索引文件。

全量同步和增量同步有什么区别？

全量同步会完整扫描网盘目录并生成 / 校验全部 STRM；增量同步依据清单（file_id + SHA1）只处理新增、变更、移动、删除的文件，速度快、请求量小，适合定时执行。

登录后提示密码错误 / 忘记密码怎么办？

登录接口有 IP 限流（5 次 / 5 分钟），等待后重试。忘记密码可重置环境变量 ADMIN_PASSWORD 重启容器；或在服务器上删除 / 修改 local_account.json 后重启。

115 账号被风控怎么办？

在「核心配置 → 115 API 间隔」中调大请求间隔；尽量使用增量同步代替全量同步；多个任务并行时系统会自动排队（任务队列按类型串行 + 限流重试）。

如何迁移服务器？

备份 data/ 与 config/ 目录（或使用备份功能导出 zip），新服务器恢复后若 STRM 内的服务器地址变了，用「特色工具 → STRM 批量替换」一键替换 URL 前缀。

如何升级版本？

Docker：docker compose pull && docker compose up -d。数据在命名卷中不受影响；登录页 / 系统页可查看版本号与 GitHub 更新提示。
